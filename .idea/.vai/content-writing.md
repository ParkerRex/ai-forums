# X & LinkedIn Posting Guidelines

## Core Voice & Tone
- **Casual and direct** - Write like you're texting a dev friend
- **Show, don't hype** - Let the work speak for itself
- **Builder-first mindset** - "You can just build things"
- **Zero fluff** - No "game-changing," "revolutionary," "this is wild"
- **Subtle flex energy** - Share wins matter-of-factly

## Post Structures

### 1. The Technical Share
**Hook → Technical breakdown → Punchline**
```
Btw that [thing] was done by an AI agent I vibe coded in [tool]:

- Technical detail
- Technical detail  
- Technical detail
- Result/process

You can just build things.
```

### 2. The Contrast Post
**Setup comparison → Call out the irony → Make your point**
```
while [company] spent $[amount] on [thing], this random guy on reddit built and open sourced the exact same product

[Evidence/link]

Just felt this kind of tech shouldn't raise so much of the world's capital for it .-.
```

### 3. The Tip Drop
**"[Role] pro tips:" → Actionable bullets → Optional example**
```
Vibe coding pro tips:

- Go slower and enjoy the creation process
- Look at the code to understand (some of) it
- Log your sessions for future context
- Create a full plan but don't give it to the agent
- Instead, "vibe" and chat to slowly build features

[Optional: screenshot of terminal/code]
```

### 4. The Opportunity Call
**Bold claim → Market insight → Simple playbook**
```
[Group] should be building [thing] ASAP

An entire market is wide open and completely untapped right now. The opportunity is massive.

Here's the simple 3-step playbook:

1) Find a painkiller problem to solve
2) Build solution with [tool]
3) [Monetization/distribution]

Example: [specific example with metrics]
```

### 5. The Meme Commentary
**[meme/image] → One-liner observation**
```
graphic designers reacting to chatgpt images right now

[THIS IS FINE meme]
```

## Content Mix
- **40%** Technical builds/demos
- **30%** AI tool tips and workflows  
- **20%** Industry commentary/takes
- **10%** Memes/lightweight observations

## Technical Details
- **Formatting:** Clean bullet lists with single dash (-)
- **Code/tools:** Always specify exact tools (Cursor, Claude Code, Cloudflare Workers)
- **Links:** Include GitHub repos and live demos when relevant
- **Emojis:** Sparse use - mainly .-.  or contextual ones
- **Tags:** Only tag when directly relevant (@CloudflareDev, @serafimcloud)

## Language Patterns
- "Btw" for casual intros
- "You can just build things" as a closer
- "Vibe coding" for AI-assisted development
- Parenthetical asides for subtle points
- Lowercase for casual feel, proper caps for emphasis

## What to Avoid
- Asking for follows/engagement
- Hashtags (except ironically)
- Corporate speak or buzzwords
- Overhyping or breathless excitement
- Long explanations - show don't tell

## Platform Notes
- **X:** Use long-form posts up to 25k chars. Break into thread only if external link + >280 chars
- **LinkedIn:** Mirror exact same text, no modifications
- **Images:** Screenshots > polished graphics. Terminal outputs welcome
- **Timing:** Post when inspired, no fixed schedule

## Engagement Style
- Only reply to thoughtful technical questions
- Ignore/mute low-effort responses
- Let the work generate organic discussion
- Focus on building and shipping over engagement farming

## Examples of Your Voice
- "Nice little Claude Code development kit"
- "Lots of people have asked me about custom rules/commands for:"
- "Just felt this kind of tech shouldn't raise so much of the world's capital"
- "All this vibe coding is making me hungry..."

## Quick Checklist
✓ Does it show something I built/discovered?
✓ Is it genuinely useful to other devs?
✓ Did I avoid hype words?
✓ Would I text this to a dev friend?

If yes to all → ship it
