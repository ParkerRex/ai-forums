**Open Questions**
===================
- *Avatar upload*: should we build a custom Convex action to obtain a presigned upload URL (e.g. Cloudinary/UploadThing) or accept a user-supplied image URL only?
- *Stats aggregation*: are post/comment/vote counts required to be real-time, or can we cache them (e.g. daily job) to avoid expensive runtime queries?
- *Skills taxonomy*: free-text tags or controlled vocab list?  Do we allow duplicates / case differences?

**Resolved Decisions**
---------------------
• *Avatar source*: default to Clerk profile image (`identity.imageUrl`). Allow optional custom upload (UploadThing) stored as `avatarUrl`; if absent, UI falls back to Clerk image → initials.
• *Stats aggregation*: counts can be **cached**. We'll persist `postCount`, `commentCount`, `netVoteCount` on the member doc and update them via write-time hooks + nightly cron job.
• *Skills taxonomy*: use a **controlled list**; enforce lowercase, de-duplicate. Provide auto-suggest with top skills (TypeScript, React, Next.js, Python, FastAPI, Vite, shadcn/ui, etc.).
